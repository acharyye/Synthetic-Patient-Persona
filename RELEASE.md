# v0.3 — The environment release

Results were always a function of seeds and declared assumptions. This release
adds the term that had been travelling undeclared: the **environment**.

Nothing about the simulation changed. What changed is that the environment is
now declared, locked, verified across every supported interpreter, and stamped
into every artifact that claims reproducibility.

## Why this is a release and not a patch set

Four bugs surfaced in three days. They look unrelated and are one species.

| | what broke | why it was invisible |
|---|---|---|
| `networkx` | imported, never declared | present in the author's venv, absent from a clean install — nine test modules failed to import for anyone else |
| `sh` / dash | `. .venv/bin/activate` in the E2E bootstrap | sourcing a missing file is a special-builtin failure; POSIX sh exits. The author's box HAD a `.venv`, so the fallback branch was never taken |
| Neumaier | CPython 3.12 changed `sum()` over floats | same inputs, same order, `110.88000000000005` on 3.11 against `110.88` on 3.12+ — a golden moved with no code change and identical draws |
| venv drift | dev venv on numpy 2.5.1 under a lock naming 2.5.2 | every "verified before push" had been running against an environment the repo does not declare |

**Every guarantee was real only in the environment that happened to exist.**
That includes, on the last line, the verification environment itself — caught by
a branch its author had marked *should not be possible*, firing on first real
use, against the author's own machine, forty minutes after the mechanism
existed.

Four patches would have left the fifth instance waiting. So the fix is one
construction.

## What the construction is

**Declared.** `[project.dependencies]` in `pyproject.toml` is the single
declaration. `uv.lock` resolves it across every supported interpreter.
`requirements.txt` is a *rendering* of the lock — regenerated by
`scripts/sync_deps.sh`, never edited — so every install path that already
pointed at it keeps working, including a clone-and-`pip install` with no uv
present.

One export serves every version: uv emits environment markers, so
`numpy==2.4.6 ; python_full_version < '3.12'` sits beside
`numpy==2.5.2 ; python_full_version >= '3.12'` in one file. Exports targeting
3.11, 3.12 and 3.13 are byte-identical.

**Locked to artifacts, not versions.** The export carries `--hash` lines and pip
verifies them. Hash-checking mode refuses anything unlisted, so a missing
transitive dependency fails at install rather than as a later import error.

**Sync enforced by construction.** CI regenerates `requirements.txt` and diffs
the bytes. No mtime heuristic, no trust that the author remembered. It lives in
the main workflow, and everything else depends on it, so a stale lock stops the
run.

**Version-stable arithmetic.** Float accumulation in core code uses `math.fsum`,
which is exactly rounded on every interpreter, or explicit fixed-arity addition
(which is why `simulation/hazard.py` was already correct — it is *variadic*
`sum()` whose algorithm CPython owns). `tests/test_float_accumulation.py` walks
the core AST and fails on any bare `sum()` whose operands are not stated;
integer accumulation carries an `# int-sum: Model.field` marker resolved through
pydantic introspection, so a field migrating to `float` breaks the test at the
moment the annotation changes. **8 of 10 markers verify against a schema; the
2 that cannot — Neo4j driver rows — are enumerated by the test rather than
remembered.**

**Verified everywhere, per push.** The CI matrix runs the Python suite including
the byte-exact goldens on 3.11, 3.12 and 3.13. The guard mechanically excludes
the one mechanism found; the matrix asserts the conclusion. A golden diverging on
one interpreter while the guard is green is not flake — it is a new
version-sensitive mechanism and the finding is the valuable part.

**Stamped, and enforced in tiers.** Baselines, verdicts and evidence bundles
record python version, numpy version and the lock hash. Severity scales to what
the evidence can distinguish, the same rule that makes a FAIL require
sign-stability:

- **refuse** on a lock-hash mismatch — different artifacts are a different
  environment and nothing vouches for an undeclared one
- **warn** on an interpreter difference inside the supported range — the matrix
  is standing evidence that this is safe, and the warning says so
- **refuse** outside the supported range — no leg covers it

The warn tier is only honest while the matrix keeps running goldens on every
interpreter. That dependency is written next to the policy it qualifies.

## What is pinned, and what is not

Everything that could be pinned by a test, is: **859 Python tests** across three
interpreters, 27 SPA tests, 3 E2E specs, all run by
`.github/workflows/tests.yml` on every push. Determinism, replay purity, exact
Shapley efficiency, the PSD gate, retention bands under two master seeds, the
citation gate, memory semantics under permutation, no-LLM-on-the-CI-path, that
the gate can actually fail, and now that float accumulation cannot silently
become interpreter-dependent.

The environment moved from **assumed** to **stamped and checked**.

`requires-python = ">=3.11"` is now true for the goldens as well as the
contracts — and true by construction rather than by audit. Not "every float
`sum()` was found", but "a new one cannot get in".

## Still open

- **Prompt v2 has not been re-recorded.** The doubled-citation fix in v0.2 is
  renderer-side only; `PROMPT_VERSION 1`'s stale inline-citation instruction is
  still the recorded configuration. `model_recall` also passed at exactly its
  0.5 bar and wants a confirming second reading.
- `ingest/synthea_loader.py` remains the one open build-order item, so
  `cohort/epidemiology.py` priors are still literature ballparks. Never quote a
  number from that module as a finding.
- `cumulative_burden_weight` still ships **frozen at zero**, unidentifiable from
  two anchors. Separating it from `burden_increment_weight` needs a third anchor
  varying per-visit burden at fixed visit count.

## Running it

```bash
python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
export PYTHONPATH=src
python scripts/quickstart.py                      # offline, end to end
uvicorn spp.api.main:app --port 8000              # API
cd ui && npm install && npm run dev               # Scenario Lab
pytest && cd ui && npm test && npx playwright test
```

Adding a dependency: edit `[project.dependencies]`, run `uv lock`, then
`scripts/sync_deps.sh`. CI fails if the rendering is stale.
