# Declare the environment, then enforce it in tiers

**Decision (v0.3):** the environment is a declared term of every result, stamped into every artifact
that claims reproducibility, and enforced at three severity tiers.

## The finding that forced it

Four bugs surfaced in three days. They look unrelated and are one species:

| What broke | Why it was invisible |
|---|---|
| `networkx` imported, never declared | Present in the author's venv, absent from a clean install — nine test modules failed to import for anyone else |
| `. .venv/bin/activate` in the E2E bootstrap | Sourcing a missing file is a special-builtin failure; POSIX sh exits. The author's box HAD a `.venv`, so the fallback branch was never taken |
| Neumaier / CPython 3.12 `sum()` | Same inputs, same order: `110.88000000000005` on 3.11 vs `110.88` on 3.12+ — a golden moved with no code change |
| venv drift | Dev venv on numpy 2.5.1 under a lock naming 2.5.2 |

> **Every guarantee was real only in the environment that happened to exist** — including, on the
> last line, the verification environment itself.

Four patches would have left the fifth instance waiting. The fix is **one construction**, not a patch set.

## The tiers

| Condition | Tier | Reasoning |
|---|---|---|
| Lock-hash mismatch | **refuse** | Different artifacts are a different environment; nothing vouches for an undeclared one |
| Interpreter difference **inside** the supported range | **warn** | The CI matrix is standing evidence that this is safe, and the warning says so |
| Outside the supported range | **refuse** | No leg covers it |

**The warn tier is only honest while the matrix keeps running goldens on every interpreter.** That
dependency is written next to the policy it qualifies — if the matrix stops, the tier must change.

## The construction

- `[project.dependencies]` in `pyproject.toml` is the single declaration; `uv.lock` resolves it
  across every supported interpreter.
- `requirements.txt` is a **rendering** of the lock — regenerated by `scripts/sync_deps.sh`, never
  edited. CI regenerates it and diffs the bytes; a stale lock stops the run.
- Float accumulation in core code uses `math.fsum` or explicit fixed-arity addition.
  `tests/test_float_accumulation.py` walks the core AST and fails on any bare `sum()` whose operands
  are not stated. The claim is **not** "every float `sum()` was found" — it is "a new one cannot get in".
